Setup Guide
Complete walkthrough: from zero to automated PR reviews in 5 steps
1
Clone & Configure
Clone the repository and set up your environment variables. You'll need an Anthropic API key, a GitHub token, and optionally SendGrid/Slack credentials for notifications.
# Clone the repo git clone https://github.com/VaibhavBansal26/multi-agent-code-review cd multi-agent-code-review # Copy the environment template cp .env.example .env # Edit .env — add your credentials ANTHROPIC_API_KEY=sk-ant-... GITHUB_TOKEN=ghp_... GITHUB_WEBHOOK_SECRET=your-random-secret
2
Start the Services
Use Docker Compose to start the API, Celery worker, Redis queue, and PostgreSQL database with one command.
# Start all services docker compose up -d # Run database migrations docker compose exec api alembic upgrade head # Verify the API is healthy curl http://localhost:8000/health # → {"status":"ok","version":"1.0"}
The dashboard is served at http://localhost:8000/dashboard once the API starts.
3
Expose the Webhook (Local Dev)
GitHub needs a public URL to send webhook events. Use ngrok to create a secure tunnel to your local API.
# Install ngrok: https://ngrok.com/download ngrok http 8000 # ngrok will print your public URL: # Forwarding https://abc123.ngrok.io → localhost:8000 # Your webhook URL will be: https://abc123.ngrok.io/webhook/github
4
Add the GitHub Webhook
In your GitHub repository settings, add a webhook pointing to your MACRV instance. Set the content type to JSON and trigger on pull request events.
# Navigate to your GitHub repository Settings → Webhooks → Add webhook Payload URL: https://<your-domain>/webhook/github Content type: application/json Secret: <same value as GITHUB_WEBHOOK_SECRET in .env> Events: ✓ Pull requests ✓ Pull request reviews (optional)
After saving, GitHub sends a ping event. Check the webhook delivery log — a green tick means MACRV received it successfully.
5
Open a Pull Request
Create a pull request on the connected repository. MACRV automatically picks it up, runs the full LangGraph pipeline, and posts findings as inline PR comments.
# Create a feature branch and push a PR git checkout -b feat/example-change echo "# change" >> README.md git add . && git commit -m "test: trigger MACRV review" git push -u origin feat/example-change # Then open a PR on GitHub # MACRV posts a review within ~30–90 seconds
Watch the review appear in real time on this dashboard — the PR Reviews page shows live status as the pipeline progresses: Queued → In Progress → Completed.
1
GitHub Repository Webhook
Go to github.com → Your Repository → Settings → Webhooks → Add webhook. Fill in the fields below:
Payload URL https://<your-macrv-host>/webhook/github Content type application/json Secret <value of GITHUB_WEBHOOK_SECRET env var> Which events? ☑ Let me select individual events ✓ Pull requests
The webhook secret is used to verify that events actually come from GitHub. Generate a strong random secret: openssl rand -hex 32
2
Verify Delivery
After saving the webhook, GitHub immediately sends a ping event. Check the Recent Deliveries section — a ✅ green check means MACRV received and validated the signature correctly.
# Check MACRV logs for the ping docker compose logs api | grep ping # → INFO: Webhook ping received from repo org/name
3
Custom .macrv.yml (Optional)
Drop a .macrv.yml file in your repo root to customize thresholds, ignored paths, and model overrides.
# .macrv.yml — customize MACRV behavior per-repo severity_thresholds: block_on: [critical] notify_on: [critical, suggestive] ignore_paths: - "*.md" - "docs/**" - "migrations/**" models: orchestrator: claude-opus-5-5 workers: claude-sonnet-4-6 classifier: claude-haiku-5-5
🎬 End-to-End Demo Flow
This demo creates a real PR with a SQL injection vulnerability and shows it flowing through the entire MACRV pipeline.
1️⃣
Create PR
Push code with a SQL injection bug
2️⃣
Webhook Fires
GitHub POSTs to MACRV /webhook/github
3️⃣
Pipeline Runs
SAST → AI Review → Classify → Notify
4️⃣
Dashboard Updates
Critical finding → REQUEST_CHANGES posted
Demo Script
#!/bin/bash # MACRV demo: vulnerable Python file triggers critical finding # 1. Create the demo repository structure mkdir -p macrv-demo && cd macrv-demo git init && git remote add origin https://github.com/YOUR-ORG/YOUR-REPO.git # 2. Write a file with a SQL injection vulnerability cat > app.py <<'EOF' def get_user(user_input): # ⚠️ This is intentionally vulnerable for the demo query = f"SELECT * FROM users WHERE name = '{user_input}'" return db.execute(query) EOF # 3. Open the PR git checkout -b demo/sql-injection git add . && git commit -m "demo: add user search (vulnerable)" git push -u origin demo/sql-injection # → Then open a PR on GitHub # 4. Watch the dashboard: Reviews page shows status change # In ~30–90s, MACRV posts a "REQUEST_CHANGES" review with: # 🔴 Critical: SQL Injection in app.py:3
Once the review appears in GitHub, come back to this dashboard → PR Reviews tab to see the finding, then Findings tab to see the detailed security report.
🧪 Run Built-in Eval Suite
The eval harness runs 6 built-in test cases (SQL injection, XSS, hardcoded secrets, clean code, command injection, style issues) and reports F1 / decision accuracy. No real PRs needed.
